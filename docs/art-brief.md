# 需求闯关 · 美术与声音设计需求（Brief）

> 给插画师 / 动画师 / 音频设计师，或其他 AI 设计工具。读完这一份就能开工；交付物按第 6 节的格式交，可以直接接进游戏代码。

---

## 0. 产品一句话

**需求闯关**：用户说一句模糊的需求（「想买第一辆车」「想给爸妈装修卫生间」），我们把它变成一局 5～7 分钟的手机小游戏。用户在剧情、对话、拖拽、取舍里，不知不觉说出自己的真实情况和真实想法，最后拿到一份清单和方案。

- **平台**：手机竖屏为主（375–430 px 宽），也会嵌在 ChatGPT / Claude 的对话窗口里（宽约 400–700 px）。
- **对标**：多邻国（Duolingo）的质感，但不是学习软件。我们像「一群性格鲜明的朋友，陪你把一件事想清楚」。
- **现在的问题**：画面拼凑（emoji 图 + 代码画的小人 + 通用按钮），有廉价感、AI 味。**这次要建立统一的画风和角色。**

---

## 1. 整体美术方向

### 1.1 关键词

**温暖 · 生活感 · 有点幽默 · 干净 · 不幼稚**

- 用户是 25–45 岁的成年人，在做花钱、关乎家庭的决定。画面可以可爱，但**不能像儿童绘本或幼儿 App**。
- 参考方向：多邻国的扁平角色（大块面、粗轮廓、夸张表情）+ 生活漫画的小细节（马克杯上的磕痕、沙发上的毯子）。
- **不要**：3D 写实、赛博朋克、科技蓝渐变、商务插图风（举手比耶的小人）、AI 图常见的过度光滑和塑料感。

### 1.2 画风规格（所有素材统一遵守）

| 项目 | 规格 |
|---|---|
| 造型 | 扁平矢量，大块面，少量形状构成；头身比约 1:2.2（Q 版但不婴儿化） |
| 轮廓 | 统一深色描边 **#3A2A26**，粗细 3px（以 400px 高的角色为准），线头圆角 |
| 上色 | 平涂 + **一层**柔和的暗部（光从**左上**来，暗部在右下），不要渐变高光 |
| 阴影 | 物体脚下一块椭圆投影，颜色 rgba(40,25,15,0.25) |
| 主色板 | 见下表；每个角色有一个「代表色」，用在上衣上，便于一眼区分 |
| 留白 | 角色和物件外围留 8% 透明边，方便动画和缩放 |

**主色板（UI 和场景共用）**

| 用途 | 颜色 |
|---|---|
| 主绿（正确 / 前进） | #22C55E |
| 暖黄（提示 / 金币） | #F59E0B |
| 天蓝（信息） | #38BDF8 |
| 玫红（危险 / 错误） | #F43F5E |
| 墨色（文字 / 描边） | #3A2A26 / #334155 |
| 纸色（背景） | #FFF8EE |

## 2. 角色（最重要）

### 2.1 原则

1. **不带职业特征**。同一个角色在不同关卡里会演医生、销售、房东、家人（游戏会给他一个「身份」标签）。所以**不能有**安全帽、白大褂、听诊器、工牌、制服这类道具。职业由台词和标签表达，不由衣服表达。
2. **靠轮廓和招牌动作区分**。把角色涂成纯黑剪影，也应该认得出是谁（发型、体型、姿态不同）。
3. **每个角色有一个招牌表情或动作**，玩家玩两次就能记住。

|---|---|---|---|---|---|

### 2.3 每个角色要的表情（8 种）

`neutral`（平常）· `happy`（开心）· `sad`（难过）· `angry`（生气）· `surprised`（吃惊）· `worried`（担心）· `smug`（得意）· `thinking`（思考）

要求：表情主要靠**眉毛、眼睛、嘴型**变化；同一角色 8 种表情放在一起，要明显不同，同时一眼看出是同一个人。

### 2.4 每个角色要的动作

| 状态 ID | 说明 | 循环？ |
|---|---|---|
| `idle` | 站着呼吸、偶尔眨眼 | 循环 |
| `talk` | 说话：嘴巴开合 + 轻微手势（叠加在任何表情上） | 循环 |
| `walk` | 走路（地图里横向走） | 循环 |
| `wave` | 招手打招呼 | 循环 |
| `jump` | 原地跳一下（答对、开心） | 单次 |
| `party` | 双手举起庆祝 | 循环 |
| `signature` | **招牌动作**（见 2.2） | 单次 |
| `react_good` / `react_bad` | 听到用户回答后的反应：点头 / 皱眉摇头 | 单次 |

### 2.5 两种构图

1. **全身**：站在场景里、地图上。画布 400×660，脚底在画布底部往上 4%。
2. **半身头像**：对话气泡旁、视频通话、卡片顶部。画布 400×400，头和肩，头部占画面 60%。

## 3. 场景（背景插画）

风格要求：比角色**降一档饱和度**，细节集中在边缘，**中间留出空地**（游戏要在中间放可交互的东西）。光统一从左上来。每个场景分 3 层：**远景 / 中景 / 前景装饰**，方便做视差和动画。

| 场景 ID | 用在 | 内容 | 必须留空的区域 |
|---|---|---|---|
| `town_map` | 地图关（在小镇里走动、找人打听） | 俯视略带透视的小镇：道路、几块空地（放地点建筑）、树、长椅 | 画面中间 70% 可以放 2–5 个地点 |
| `room` | 摆进生活（室内） | 客厅：墙、窗（阳光斜进来）、木地板、地毯、绿植、挂画 | 地面上 3–4 个可摆放位置 |
| `yard` | 摆进生活（户外 / 农村） | 院子：远山、栅栏、草地、树、小棚子 | 同上 |
| `office` | 摆进生活（办公室） | 工位区：大窗户 + 城市、地毯、绿植 | 同上 |
| `street` | 摆进生活（街道 / 停车） | 街道：楼、人行道、马路、路灯、树 | 同上 |
| `day_morning` / `day_noon` / `day_evening` / `day_night` | 无文字的一天 | **同一个**街景的四个时段：天色、光影、窗户灯光、路灯不同 | 中下部站人和一个道具 |
| `stage` | 连环取舍（Reigns 式卡牌） | 小剧场：红幕布、聚光灯、木地板 | 中间放一叠卡片 |
| `tidy_table` | 整理归类 | 暖色墙 + 置物架 + 木桌，桌上空着 | 桌面放 3 个容器，墙面空着放卡片 |
| `boss_arena` | Boss 战 | 戏剧化的「危机现场」：暗色、警示光、风雨或裂缝，有压迫感但不恐怖 | 中间放一个「危机」大物件 |
| `home_bg` | 首页 | 乐乐站在一张写满待办便签的软木板前，温暖、邀请感 | 下半部放输入框 |
| `win_bg` | 通关页 | 彩带、聚光、领奖台的感觉 | 中间放角色和分数 |

**规格**：每个场景出 **1080×1920（竖屏，9:16）**，并单独提供每一层。

## 4. 物件图标

游戏里的「东西」（水泵、婴儿车、充电桩……）是 AI 根据需求**临时生成**的，没法每样都画。所以：

1. **常用物件画一套固定图标**（约 120 个）。按类别：家电、家具、交通、宠物、育儿、健康、数码、工具、钱和票据、建材、食物、服务（保洁、维修、保险），以及时间和天气。首批清单单独给。
2. **其余的用开源的统一风格 emoji 兜底**。建议换成 **Microsoft Fluent Emoji（3D 或 Flat 风格，MIT 许可）**，替换现在的 Google Noto，并在其上统一加一圈描边和投影，向我们的画风靠拢。
3. 图标规格：**256×256**，带 8% 透明留白，统一左上光，统一投影。

## 5. UI 组件

在现有布局基础上统一皮肤，不改交互：

- 按钮（主 / 次 / 危险 / 禁用；按下有「压下去」的厚底效果）
- 选项卡片、对话气泡（角色 / 我 / 提问）、底部反馈条（对 / 错 / 风险 / 翻车）
- 顶栏：进度条、红心、连击火焰、预算徽章
- 地点标记（感叹号 / 对勾）、分类筐（纸箱 / 篮子 / 垃圾桶）、四个药瓶（钱 / 省心 / 效果 / 安全）
- 分享海报模板（1080×1920）：4 种「需求人格」各一套配色和装饰

**字体**：中文「阿里巴巴普惠体」或「HarmonyOS Sans」的 Heavy / Bold（免费商用）；英文 **Nunito** Black / ExtraBold。

## 6. 交付格式（按这个格式交，开发能直接用）

### 6.1 角色动画：**Rive**（首选）

多邻国的角色动画用的就是 Rive。每个角色交一个 `.riv` 文件：

- **画板 (Artboard)**：`full`（400×660）和 `bust`（400×400）各一个
- **状态机 (State Machine)**：名字统一叫 `main`，输入 (Inputs) 统一为：

| 输入名 | 类型 | 取值 |
|---|---|---|
| `mood` | Number | 0 neutral · 1 happy · 2 sad · 3 angry · 4 surprised · 5 worried · 6 smug · 7 thinking |
| `talking` | Boolean | 说话时为 true（嘴动 + 手势，叠加在表情上） |
| `act` | Number | 0 idle · 1 walk · 2 wave · 3 jump · 4 party |
| `signature` | Trigger | 播放招牌动作 |
| `reactGood` / `reactBad` | Trigger | 听到回答后的反应 |
| `lookX` | Number | -1 ~ 1，眼睛往左右看 |

- 文件命名：`char_<id>.riv`，例如 `char_lele.riv`
- 每个文件不超过 300 KB

**如果没有 Rive**：退而求其次，交 **SVG 分层**（每个部件单独一个 `<g>`，按 `head` `hair` `eyes_<mood>` `mouth_<mood>` `brows_<mood>` `body` `arm_l` `arm_r` `leg_l` `leg_r` 命名，旋转中心标在关节处）。现有代码就是这么拼动画的，可以直接替换。

### 6.2 场景和图标

- 场景：`scene_<id>_<layer>.webp`（layer = far / mid / front），1080×1920，另交一张合成预览 PNG
- 图标：`icon_<name>.svg`（首选）或 `icon_<name>.png` 512×512
- 所有源文件（Figma / AI / PSD）一并交付

### 6.3 验收标准

1. 9 个角色并排、全部涂黑成剪影，能分辨谁是谁
2. 同一角色 8 个表情放一排，表情差别明显，仍是同一个人
3. 任何场景 + 任何角色 + 任何图标放在一起，**看不出是不同人画的**
4. 缩到 48px（对话头像大小）仍能认出角色

## 7. 声音

### 7.1 方向

**温暖、俏皮、有弹性**。木琴、拨弦、马林巴、钟琴、轻打击乐为主。参考多邻国和「动物森友会」的 UI 声音：短、圆润、不刺耳，**每个操作都有「被回应」的满足感**。Boss 战可以突然变得激昂，形成反差。

### 7.2 音乐（全部可无缝循环）

| ID | 用在 | 风格 | 速度 | 时长 |
|---|---|---|---|---|
| `bgm_home` | 首页 / 等待生成 | 轻快、邀请感，尤克里里 + 口哨 + 轻打击 | ~100 BPM | 60–90 s 循环 |
| `bgm_story` | 剧情 / 聊天（**音量很低**，在台词下面） | 温暖钢琴 + 拨弦，留出人声空间 | ~85 BPM | 60 s 循环 |
| `bgm_explore` | 地图 / 摆进生活 / 整理 | 好奇、轻松，马林巴 + 钟琴 | ~110 BPM | 60 s 循环 |
| `bgm_tension` | 连环取舍 | 有点悬念的拨弦 + 时钟般的节奏 | ~120 BPM | 45 s 循环 |
| `bgm_boss` | Boss 战 | **激昂**：鼓组 + 贝斯 + 铜管或合成主旋律，小调，有「决战」感 | ~150 BPM | 60 s 循环，带 2 s 开场上冲 |
| `bgm_day_*` | 无文字的一天（早 / 午 / 傍晚 / 夜各一段） | 同一主题的四种配器：早晨长笛 + 鸟鸣，中午明亮，傍晚慵懒，夜里八音盒 + 虫鸣 | ~90 BPM | 各 30 s 循环 |
| `jingle_win` | 通关 | 欢快的胜利号角 | — | 3–5 s |
| `jingle_lose` | 翻车 | 滑稽的「哇哦哦」下行，不是惨败 | — | 2 s |
| `jingle_level` | 每完成一个小玩法 | 短上行琶音 | — | 1 s |

### 7.3 音效

每个音效交 **2–3 个变体**（随机播放，避免听腻）。

| ID | 时机 | 感觉 | 时长 |
|---|---|---|---|
| `ui_tap` | 普通点击 | 轻、干净的「嗒」 | <80 ms |
| `ui_select` | 选中卡片 / 选项 | 「啵」+ 轻微上扬 | <150 ms |
| `ui_back` | 取消 / 收起 | 下行的「嗒」 | <120 ms |
| `correct` | 答对 / 好选择 | 明亮双音「叮叮」 | ~400 ms |
| `wrong` | 出问题 | 闷的双音下行，不刺耳 | ~400 ms |
| `pickup` | 拿起拖动的东西 | 「嗖」上扬 | ~150 ms |
| `drop_1`…`drop_6` | 放进筐 / 放到位置（连击时依次升调） | 「啵」+ 钟琴一声，六个音按五声音阶升高 | ~400 ms |
| `thud_wood` | 东西落地 | 木头的闷响 | ~200 ms |
| `sparkle` | 闪光、星星 | 一串高音叮铃 | ~500 ms |
| `buzz` | 放错地方 | 卡通的「嗡嗡」 | ~400 ms |
| `swoosh_l` / `swoosh_r` | 卡片甩出 | 风声（左右声像） | ~250 ms |
| `meter_up` / `meter_down` | 药瓶涨 / 跌 | 液体「咕嘟」上 / 下 | ~300 ms |
| `heartbeat` | 某条槽快见底 | 低沉心跳两下 | ~600 ms |
| `crash` | 翻车 | 卡通的「哐当」+ 玻璃碎 | ~800 ms |
| `shutter` | 拍立得 | 相机快门 | ~200 ms |
| `tick` | 时间流逝 | 时钟滴答 | ~100 ms |
| `coin` | 省钱 | 金币「叮」 | ~300 ms |
| `stamp` | 盖章（整理完毕） | 「啪」 | ~200 ms |
| `boss_hit` | Boss 出招 | 重击 + 混响 | ~600 ms |
| `amb_birds` / `amb_crickets` / `amb_city` / `amb_room` | 环境声 | 轻柔可循环 | 10–20 s 循环 |

### 7.4 技术规格

- 格式：**OGG（Vorbis）+ M4A（AAC）各一份**，44.1 kHz，立体声（音效可单声道）
- 响度：音乐 **-18 LUFS**，音效峰值 **-3 dBFS**，所有音效之间响度一致
- 循环点处理干净（交付时注明循环起止点）
- 总包大小：音乐合计 **≤ 4 MB**，音效合计 **≤ 1 MB**（手机网页要秒开）
- 命名：`bgm_*.ogg` / `sfx_<id>_<n>.ogg`
- **版权**：必须是可商用、可在网页和 App 内使用的授权（原创，或注明授权来源和许可证）

## 8. 给 AI 设计工具的提示词模板

> 用 Midjourney / 即梦 / Recraft 之类工具出角色时，可以从这个模板开始，然后**人工统一修正**描边和配色。

**角色全身：**
```
flat vector character, Duolingo-like style, thick dark brown outline (#3A2A26), flat colors with one soft shadow from top-left, chibi proportions head:body 1:2.2, adult not childish, full body standing, plain white background, no text, no profession props.
Character: <外形关键词，英文>, main color <代表色>, expression <mood>, pose <动作>
```

**表情表：**
```
same character, expression sheet, 8 expressions in a 4x2 grid: neutral, happy, sad, angry, surprised, worried, smug, thinking, head and shoulders, consistent design, flat vector, thick outline
```
